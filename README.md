# π 计算器（PiCalculator）

一个运行在 Windows 本机的桌面 π 计算工具：以当前公认最高效的 **Chudnovsky 级数 + 二分分裂 + GMP 大数乘法**为核心的任意精度 π 计算引擎，配以简洁的 PySide6（Qt 6）图形界面。它把"算 π"变成一件可观察的事——实时显示已完成位数、计算速率与预计剩余时间，像流水一样滚动展示最新的数字，任何时刻都能暂停、保存、关闭再继续，而最终结果会确定性地写入一个纯文本文件，并带有三层可独立审计的正确性证据。

## 核心特性

**实时计算与展示。** 计算以约一秒为粒度分块推进，界面持续刷新：已完成位数（含目标进度与 ETA 估算）、实时速率（位/秒与位/分可切换）、内存占用与阈值。数字显示区只滚动展示"已经不可能再改变"的稳定前缀——工具从不展示未经证明的数字。

**随时的暂停 / 保存 / 继续。** 暂停按钮是一个开关：暂停后一键继续；也可以直接关闭程序，进度会以原子方式写入检查点。下次打开选择"继续会话"，秒级从检查点恢复（检查点不可用时自动降级为重演，代价不超过已花时间）。同一次计算无论暂停多少次、重启多少遍，最终产出的文件与一次性算完**逐字节完全一致**。

**三层正确性校验。** ① 与内置权威常数（π 前 1000 位十进制、前 64 位十六进制）逐位比对；② 完成后计算整文件 SHA-256（流式，支持 GB 级文件）；③ 可随时运行 BBP 公式在任意十六进制位置做独立抽查——两套完全不同的算法分开计算同一窗口并对照，互不共享代码。

**面向大规模设计。** 计算状态用"二叉计数树"累积：块小到约一秒也不会产生额外开销，因此暂停响应、数字刷新粒度与大位数计算性能可以兼得。内存监控在超过阈值时自动暂停并提示，避免超大位数（乃至十亿位级）把机器拖垮。

**实用的小功能。** π 数字搜索（找生日、找序列，支持跨行匹配并给出小数位序号）、0–9 数字频率统计条形图、深/浅色主题一键切换、历史会话列表、复制前缀、gzip 压缩导出。

**无界面运行模式。** 计算引擎可脱离 GUI 独立运行（`python -m pi_tool.engine.worker`），便于脚本化、批处理与调试。

## 技术架构

项目按"计算内核 / 界面 / 公共协议"三层组织：

```
pi_tool/
  engine/    计算内核（可独立测试，无 GUI 依赖）
    chudnovsky.py  二分分裂与运行态（计量树累积）
    decimal.py     稳定前缀提取（整数化十进制/十六进制）
    checkpoint.py  检查点二进制格式（原子写入、口径快照校验）
    bbp.py         BBP 公式独立实现（交叉校验）
    verify.py      常数比对 / 流式 SHA-256 / 交叉校验编排
    worker.py      子进程主循环：分块、暂停、保存、内存监控、日志、CLI
  app/       PySide6 界面
    main_window.py 主窗口、状态机、事件轮询、进程生命周期
    widgets.py     数字滚动区、速率/内存面板、频率图、对话框
    theme.py       深/浅两套 QSS
    history.py     会话扫描与历史记录
    search.py      mmap 数字搜索线程
    export.py      gzip 导出
  common/    常量口径、配置、进程间协议
scripts/bench.py   基准与参数校准
tests/             单元测试 + 端到端一致性测试
```

**进程模型。** 界面主进程只负责展示与交互；真正的计算运行在独立的 worker 子进程中，两者通过两个消息队列通信（命令下行、事件上行）。这带来三个好处：界面永远不被计算阻塞；暂停/停止语义简单可靠；崩溃互不影响，进度始终可从检查点恢复。子进程是唯一的 pi.txt 写入者，杜绝并发写文件问题。

**界面构成。** 主窗口自上而下是：进度条与位数/ETA；速率与内存面板；大字号等宽字体的数字滚动区；控制按钮（新计算、继续会话、暂停/继续、立即保存、停止、复制、导出）；以及统计、搜索、BBP 校验、历史、日志五个标签页；状态栏显示输出目录与最终 SHA-256。

## 算法与正确性

**算法。** Chudnovsky 级数每项产出约 14.1816 位十进制数字，配合二分分裂（把级数求和的递归合并变成大整数乘法）与 GMP 的亚二次乘法，总复杂度约为 O(M(n)·log n)，是世界纪录程序 y-cruncher 所使用的同一算法族，也是任意精度 π 批量计算的公认最优方法。

**全整数运算。** 提取十进制前缀时不做任何浮点运算：以 `π·10^m ≈ (426880 · isqrt(10005·10^(2m)) · Q) // T` 的整数形式求值，仅保留 20 位保护位，最后按需求截取。十六进制前缀同法（把 10 换成 16）。这从根上避免了浮点舍入带来的歧义。

**"稳定位数"的概念。** 级数余项呈几何式衰减（每项约小 10^14.18 倍），因此完成了 k 项后可以严格给出"前 floor(14.1816·k) − 22 位必然正确"的结论。工具只展示、只写盘这个边界以内的数字——界面上看到的每一位都已经不可能再变。

**可暂停的累积结构。** 运行态不用单一大三元组，而是维护一个"二叉计数树"：新完成的块与其等规模的相邻块合并，形成 log 层结构。单次合并开销只与本次块的大小相关、与已完成位数无关，因此块可以小到约一秒；所有合并的摊还总量仍与一次性计算同一量级。这正是"实时滚动 + 秒级暂停 + 十亿位目标"三者可以同时成立的工程核心。

**确定性与审计。** 输出文件 `pi.txt` 是流式格式：`3.` 开头，其后每 1000 个字符一行；完成时补齐尾换行。行位置只由"总字符数"决定，与分块方式、暂停次数、刷新频率无关——同一目标位数永远得到同一份字节与同一个 SHA-256。计算内核另有朴素级数逐项求和的独立对照测试、随机分块一致性测试，以及 BBP 交叉验证作为第二算法证据。

## 数据文件

完成或暂停时，输出目录中会出现四个文件：

- `pi.txt` —— 计算结果本体：纯 ASCII，`3.` 加小数位，每 1000 字符一行，可由任意文本工具打开、搜索、比对；
- `pi.session.json` —— 会话元数据：目标位数、已写出位数、稳定位数、已完成项数、耗时、0–9 数字统计、最终 SHA-256；
- `pi.checkpoint.bin` —— 可恢复的计算状态（计量树各层的大整数），采用"临时文件 + 原子替换"写入，任何时刻断电都不会留下半截文件；
- `pi.log` —— 运行日志（自动滚动，保留最近若干份）。

## 技术栈

Python 3.14（64 位）· gmpy2（GMP 绑定，大整数与快速乘法）· PySide6 / Qt 6（界面）· psutil（内存监控）· pytest（单元与端到端测试）。
