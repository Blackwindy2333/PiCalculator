# PiCalculator — π 实时计算小工具

基于 **Chudnovsky 级数 + 二分分裂 + GMP 大数乘法（gmpy2）** 的桌面 π 计算器，
界面使用 **PySide6**：实时计算、滚动显示最新稳定数字、可暂停/保存/续算，结果确定性写入 `pi.txt`。

## 环境要求

- Windows + 64 位 Python 3.14（`py -3.14`；本机唯一解释器）
- 依赖：gmpy2 / PySide6 / psutil（均有 win_amd64 预编译 wheel，无需 C 编译器）
- pip 走已配置的清华镜像即可

## 安装

```
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt    # 开发/测试
```

## 运行 / 测试 / 基准

```
run.bat
（或）.venv\Scripts\python.exe -m pi_tool
（测试）.venv\Scripts\python.exe -m pytest tests -q
（基准）.venv\Scripts\python.exe -m scripts.bench
（无 GUI 计算，供调试）.venv\Scripts\python.exe -m pi_tool.engine.worker --output-dir output\demo --target-digits 1000000
```

## 功能

- 新计算 / 继续先前计算（检查点秒级恢复；检查点不可用时自动降级重演）
- 实时位数、速率（位/秒、位/分可切换）、目标进度条与 ETA（估算）、内存占用与阈值
- 最新稳定数字滚动显示（只显示"必然正确"的数字；绝不显示未稳定位）
- 暂停 / 立即保存 / 停止：随时安全继续，最终文件与一次性计算**逐字节一致**
- 三层校验：权威常数（前 100/1000 位）比对、整文件 SHA-256、BBP 十六进制独立抽查
- π 数字搜索（找生日等）、数字频率统计（0-9 条形图）、深/浅主题切换
- 历史会话列表（继续/打开目录）、复制前缀、gzip 导出

## 输出文件（输出目录内）

- `pi.txt`：`3.` 开头，每 1000 个字符一行（首行 `3.` + 998 位），纯 ASCII，完成后补尾换行
- `pi.session.json`：会话元数据（位数/状态/统计/最终 SHA-256）
- `pi.checkpoint.bin`：计算状态（计量树各层，原子写入，可秒级恢复）
- `pi.log`：运行日志（自动滚动，5 MB × 3）

## 算法与正确性

- Chudnovsky 级数每项产出约 **14.1816 位**；二分分裂 + GMP 快速乘法，复杂度约 O(M(n)·log n)
- 全程整数运算：`π·10^m ≈ (426880 · isqrt(10005·10^(2m)) · Q) // T`，避免任何浮点舍入歧义
- 只写出 `stable(k) = floor(14.1816·k) − 22` 以内的数字（余项界 + 22 位保守余量）
- 运行态用**二叉计数树**累积：块大小可以取小到约 1 秒（暂停/刷新粒度），总合并开销仍为 O(M(N)) 量级
- 完成时写出的是"全部稳定位"，通常比目标位数多几十位（同一目标恒为同一值，不影响字节确定性）

## 实测性能（i5-11300H，`scripts/bench.py`）

| 规模 | 级数构建 | 前缀提取 | 说明 |
|---|---|---|---|
| 10 万位 | 0.026 s | 0.011 s | |
| 100 万位 | 0.42 s | 0.20 s | 分块累积（4096 项/块）总耗时 0.65 s，与一次性计算持平 |

按标度外推：1000 万位约十秒级、1 亿位分钟级、10 亿位数小时级（受内存与磁盘约束，界面有内存阈值自动暂停兜底）。

## 参考校验值（100 万位）

- 目标 100 万位完整计算（本机约 1.0 秒）：
  - `written_digits = 1000039`（完成时写出的稳定位数，同一目标恒为定值）
  - `sha256_final = 11267e35bb22e399b5f78fe63851045eed59883514291f9382a3d09a7e683375`
  - `pi.txt = 1,001,042` 字节
- 同一目标位数重跑（含中途暂停/继续任意次数、关闭重开）应得到**完全相同的字节与哈希**。

## 已知限制

- GUI 的目标位数输入上限为 20 亿（Qt 输入框为 32 位；`settings.json` 或 CLI 参数可设到 1000 亿）
- BBP 校验在超大十六进制位置会长时间占用 worker（其间不响应暂停）；界面在 10^7 位以上会先给出成本警告
- 单线程计算；多进程并行、C++ 引擎、exe 打包列为后续版本
- 每秒位速率为"已稳定位数"的增长率，刷新节流（默认 1 秒）下略有滞后
